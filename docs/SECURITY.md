# Data, permissions and isolation

The repository distributes code and synthetic examples. Secrets, configuration,
runtime identities, databases, backups, cookies, tokens and business records
remain outside Git. Static and secret scans complement human review; they do
not guarantee that every confidential item has been found.

Service roles, Application membership and per-record ACLs are distinct.
Identity is derived by the server. A form value, role label or confirmation
does not grant permission. A writer does not become a sharing administrator.
Test revocation with a still-valid session; an expired-session error does not
prove that access was removed.

The three roles, work cases and Marketing reuse native ACLs. Shared memory and
measurement files have their own boundaries: do not claim uniform per-person
ACLs for all resources. Memory requires a dedicated Agent and sidecars and
volumes for each company. Its confirmation expresses an intention to share;
it does not replace runtime identity validation.

Revoking access to a case does not remove an excerpt previously shared
intentionally with shared memory. Follow the memory review lifecycle to remove
it; private cases are never contributed automatically.

The responsible person's name in a Marketing brief is tracking information,
not a mandate or permission. Contacts remain internal references. Attesting a
first result requires evidence and a date; it is not a sale or a measurement
of adoption or attribution.

External effects remain disabled. The authorized person makes native approval
decisions. Never copy another company's grants, mandates, accounts or
configuration to accelerate an installation.
